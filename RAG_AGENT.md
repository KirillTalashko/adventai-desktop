# RAG в агенте + память задачи (День 25) — заключение недели RAG

Финал недели 5: всё, что накоплено в Дни 21–24, подключено к ОСНОВНОМУ агенту (`TaskOrchestrator`), а не только к
dev-панели. Отдельного мини-чата не делаем — RAG живёт в существующем чате задачи. RAG и MCP уживаются **аддитивно**.

> Индексация — `RAG_INDEXING.md`; реранк/фильтр — `RAG_RERANKING.md`; цитаты/источники — `RAG_CITATIONS.md`.

## Что делает агент теперь

На каждый ход отвечающих стадий (INTAKE / ASSIST / EXECUTION):
1. **ищет контекст во внутренней базе** (RAG) под последний вопрос (или текущий шаг),
2. **подмешивает выдержки** блоком `[БАЗА ЗНАНИЙ]` в промпт стадии,
3. **отвечает с учётом найденного**,
4. **всегда показывает источники** — блок «Источники (база знаний)» под ответом.

История диалога и «память задачи» сохраняются между сессиями (как и раньше — `conversations/<id>.json`).

## RAG ⇄ MCP — план сосуществования (аддитивно)

Два источника знаний, оба со ссылками, **дополняют** друг друга:

| | RAG (внутренняя база) | MCP `get_visa_requirements` |
|---|---|---|
| Что | наши 50 документов (процедуры, пояснения) | живые официальные данные + URL |
| Когда | на КАЖДОМ ответе (дёшево, детерминированно) | ОДИН раз на кейс (тяжёлый синтез, кэш в `research`) |
| Где в промпте | блок `[БАЗА ЗНАНИЙ]` | блок `[СПРАВКА ПО ВИЗЕ]` |
| Ссылки | источники `[S1] Документ › Раздел` (chunk_id — в dev-панели) | официальные `https://` URL + дата |
| Приоритет фактов | процедуры, общие пояснения | **точные сборы/сроки/куда подавать** |

Правило (в `CONDUCTOR`): точные сборы/сроки/куда подавать — приоритет живым офиц. URL из `[СПРАВКА]`; общие
процедуры — из `[БАЗА ЗНАНИЙ]`; **всегда** показывай, на что опираешься; не выдумывай сверх этих блоков. Если
в базе релевантного нет — RAG молчит (пустой блок), агент опирается на MCP/`[СПРАВКА]`.

## Как устроено (код)

- **Порт** `domain/rag/KnowledgeRetriever.kt`: `interface KnowledgeRetriever { suspend fun retrieve(query): List<KnowledgeHit> }` (чистый домен).
- **Адаптер** `data/RagKnowledgeRetriever.kt`: переиспользует `KnowledgeIndex.retrieve` (contextual + эвристический реранк + порог 0.50), `gateway = null` → без LLM, только эмбеддинг. Эмбеддер создаётся и закрывается на вызов.
- **Оркестратор** `domain/TaskOrchestrator.kt`: ctor-параметр `retriever`; `ragContext(ctx, history, queryOverride?)` строит запрос (последнее сообщение/текущий шаг + подсказки кейса `страна+цель`), формирует блок `[БАЗА ЗНАНИЙ]` с `[S1]…` и возвращает `KnowledgeHit`-и; `call(ragBlock=…)` вставляет блок рядом с `[STATE]`. Источники поднимаются в `AgentReply.sources`.
- **UI** `ui/ChatState.kt`: собирает `RagKnowledgeRetriever` и передаёт в оркестратор при `config.ragInAgentEnabled`; `renderRagSources` дописывает понятный блок «📚 Источники (наша база знаний)» под ответ. Тумблер «RAG в агенте» в настройках коннекторов (`ui/App.kt`), по умолчанию **вкл**.
- **Понятный UI (не для разработчика):** вызов MCP-инструмента рендерится человекочитаемо через `friendlyToolTraces`/`friendlyTool` в `TaskOrchestrator` («🔎 Сверяю актуальные требования: страна, цель · гражданство …») вместо сырого `name({"json":…})`; источники RAG показываются по «крошкам» раздела, без технического chunk_id/имени файла (они остаются в dev-панели Дня 24).

## Память задачи (task state) — что уточнено / ограничения / цель

Уже реализована и покрывает усиление Дня 25 (усилять не потребовалось, только удержать по ходу диалога):
- **Цель диалога** — `TaskContext.task` (+ страна/цель в досье), строка `Задача:` в `[STATE]`.
- **Что пользователь уточнил** — `CaseFile` (страна, гражданство, цель, даты, кто едет, занятость, история, город) в блоке `[ДОСЬЕ]`.
- **Зафиксированные ограничения/термины** — там же (прошлые отказы, число заявителей/детей, занятость/доход) + рабочая память (`memory.addConstraint`, напр. «дозагрузить документ»).

`CaseFile.merge` накапливает факты и НЕ затирает известное пустыми репликами (проверено харнессом на 12 сообщениях).

## Проверка

**Детерминированный verify-харнесс** (без LLM/эмбеддера, прогнан и удалён): стаб-gateway ловит системный промпт,
стаб-ретривер — запрос; подтверждено, что блок `[БАЗА ЗНАНИЙ]` + `[S1]` + `chunk_id` доходят до промпта и в
`AgentReply.sources`; запрос обогащается фактами кейса; без ретривера источников нет (аддитивность); `CaseFile`
не теряет цель за 12 сообщений. 15/15.

**GUI (живой LLM) — 2 длинных сценария по 10–15 сообщений.** Запуск: `.\gradlew.bat run` → включить RAG в агенте
(и MCP). Проверяем: агент не теряет цель, в КАЖДОМ содержательном ответе есть «Источники (база знаний)», а точные
сборы/сроки идут с офиц. ссылками из MCP.

- **Сценарий A — семья, Шенген/Франция (полный цикл задачи):**
  1) «Планируем поездку во Францию»; 2) «туризм»; 3) «гражданство РФ»; 4) «едем впятером: я, жена, трое детей»;
  5) «ориентир — октябрь 2026»; 6) «какие документы нужны?» (ждём ответ с источниками базы + офиц. ссылками);
  7) выбрать подход к плану; 8) запустить план; 9–12) идти по шагам «Продолжить» (на каждом шаге — источники);
  13) «а страховка на детей нужна?» (ASSIST, источники); 14) довести до проверки. Контроль: на шаге 13 агент
  помнит Францию/детей/даты (цель не потеряна) и снова цитирует базу.
- **Сценарий B — длинный Q&A по Таиланду (ASSIST):** 12–15 реплик про безвиз/60 дней/TDAC/визаран/продление/
  страховку/деньги. Контроль: каждый ответ несёт «Источники (база знаний)» из `thailand.md` и родственных доков,
  агент удерживает, что речь про Таиланд и туризм, не сваливаясь на общие слова.

`.\gradlew.bat compileKotlin --offline` — зелёный. Полный e2e с живой LLM — только в GUI (LLM из headless-gradle
не резолвится, DNS); детерминированная часть — харнессом.

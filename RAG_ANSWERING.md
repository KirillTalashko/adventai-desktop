# RAG Answering — первый RAG-запрос (День 22)

Правая половина RAG поверх индекса Дня 21: **вопрос → поиск релевантных чанков → объединение с вопросом →
запрос к LLM**. Два режима для сравнения (с RAG / без RAG) и контрольный набор из 10 вопросов.

> Индексация (левая половина) — `RAG_INDEXING.md`. Конспект теории — `.claude/WEEK_5_RAG.md`.

## Функция ответа

```
question
  → embed(question)              (Ollama nomic-embed-text)
  → RagSearch.topK(index, k=6)   (косинус по SQLite-индексу)
  → RagAnswerer.withContext(question, chunks)
        системный промпт: «отвечай ТОЛЬКО по [КОНТЕКСТУ]; если ответа нет —
        честно скажи, что данных нет; ссылайся на номера [1],[2]; в конце — Источники»
  → LLM (выбранная модель) → ответ со ссылками на источники
```

Реализация: `domain/rag/RagAnswerer.kt` (порт `LlmGateway`), оркестрация — `KnowledgeIndex.answer(...)`.

## Два режима (сравнение качества)

- **Без RAG** — тот же вопрос без контекста: модель отвечает из общей памяти (без источника, риск
  «правдоподобной» галлюцинации).
- **С RAG** — в промпт подмешаны найденные фрагменты нашей базы + инструкция отвечать строго по ним и
  указывать источники.

Панель показывает оба ответа с ярлыками, а под ответом «С RAG» — блок **«На чём основан ответ»**: ровно те
выдержки базы, что ушли в контекст, с раскрытием полного текста. Если ответ С RAG оказался **отказом**
(вопрос не из базы), блок честно поясняет: векторный поиск всё равно возвращает k ближайших фрагментов, но
модель их отвергла — и на карточке «Без RAG» появляется пометка **«похоже на выдумку»** (там модель
уверенно ответила, хотя данных в базе нет). Это и есть наглядная польза RAG.

`src/main/resources/rag_eval/gold_questions.json` — для каждого вопроса зафиксированы **ожидание** и
**ожидаемые источники** (`sources: []` → негативный контроль: данных в базе нет, агент обязан честно это
сказать).

ответа и авто-судит простыми признаками (без отдельной модели-судьи): опёрся ли ответ С RAG на ожидаемый
источник; на ловушке — честно ли отказался. Сверху — **сводка-история**:
- «С RAG: N/9 ответов со ссылками, из них M по нужному источнику; на ловушке честно отказался.»
- «Без RAG: 0 ответов со ссылками; на ловушке выдумал.»

## Проверено

- Индекс на реальной Ollama (`nomic-embed-text`, 768), 14 документов, structural = 102 чанка.
- Retrieval по контрольному набору: нужный источник в top-6 — **7/9** позитивных; ловушка отрабатывает
  (промахи #4 «отказ США», #5 «ОАЭ» — bi-encoder не поднял нужный документ; это мотивация **reranking**,
  следующий день).
- LLM-ответы (оба режима, прогон набора) идут через тот же `LlmGateway`, что и основной чат-агент.
  В приложении оба режима отвечают; headless-прогон упирается в капризную сеть (DNS/
  `UnresolvedAddressException`, как с mcp-visa.ru). Прокси для запросов — в «Настройках».

## Как посмотреть (демо, dev-панель «Индексация знаний (RAG)»)

1. `.\gradlew.bat run` → Настройки → режим разработчика (+ ключ LLM). Композер → иконка-БД.
2. **Шаг 1 · Построить индекс** (на 14 документов).
3. **Шаг 2 · Спросить** → «Спросить в обоих режимах»: сравнить ответы без RAG / с RAG (+ «На чём основан
   ответ»). Кнопка **«Пример: вопрос не из базы»** — показать контраст «выдумка vs честный отказ».
4. **Шаг 3 · Прогнать 10 вопросов** → сводка-история + разбор.

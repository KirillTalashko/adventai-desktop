# RAG Citations & Anti-hallucination — цитаты, источники и «не знаю» (День 24)

Финальный слой RAG поверх Дней 21–23: ответ агента **обязан** нести источники и дословные цитаты, а при
слабом контексте — честно отвечать «не знаю» и просить уточнение. Цель — проверяемый, не галлюцинирующий ответ.

> Индексация — `RAG_INDEXING.md`. Первый запрос — `RAG_ANSWERING.md`. Реранк/фильтр — `RAG_RERANKING.md`.

## Что обязан вернуть каждый ответ С RAG

```
ответ  +  ИСТОЧНИКИ (source › section · chunk_id)  +  ЦИТАТЫ (дословные фрагменты чанков)
```

- **Источники** и **цитаты** формируются кодом **детерминированно** из найденных чанков — их нельзя выдумать.
- **Цитата** = наиболее релевантное вопросу предложение чанка + смежный сосед (окно из соседних фраз;
  лексическое пересечение основ, лёгкий рус. стеммер `Ru`), а не весь чанк. Соседей берём **смежными**, чтобы
  цитата оставалась **непрерывным** дословным фрагментом текста → анти-галлюцинация «по построению».
- Реализация: `RagAnswerer.withContext` (`domain/rag/RagAnswerer.kt`) — `RagSource(n, source, section, chunkId,
  score, text)` + `Citation(n, source, section, chunkId, quote)` в `RagAnswer`.

## Режим «не знаю» (усиление)

Если фильтр по порогу релевантности (День 23) оставил **пусто** — `KnowledgeIndex.answer` НЕ зовёт LLM, а
возвращает `RagAnswerer.abstain(question)`: честное «Не знаю: в базе нет релевантной информации, уточните…».
Раз генерации нет — выдумать нечего. `RagAnswer.abstained = true` подсвечивается в панели.

```
retrieve → фильтр по порогу → after.isEmpty()?  ── да ──▶  abstain(): «не знаю» + просьба уточнить (без LLM)
                                               └─ нет ─▶  withContext(): ответ + источники + цитаты
```

## Проверка на 10 вопросах (метрики недели 5)

`KnowledgeIndex.citationEval` прогоняет контрольный набор и по каждому вопросу считает:

| Критерий | Как | Метрика |
|---|---|---|
| есть источники | `answer.sources.isNotEmpty()` | Context Relevance |
| есть цитаты | `answer.citations.isNotEmpty()` | — |
| смысл опирается на источники | модель-судья `RagFaithfulnessJudge` (да/нет) | **Faithfulness** |
| вопрос-ловушка | правильно ли сработал режим «не знаю» (`abstained`) | анти-галлюцинация |

`CitationCheck.pass`: для позитивного вопроса — источники + цитаты + faithful; для негативного — воздержался.

**Важно про Faithfulness.** Судья сверяет ответ против **полных источников** (найденных чанков), на которых
он построен, — а НЕ против одной вырезанной цитаты. Иначе оценка искусственно занижается: ответ пишется по
всему чанку (до 700 символов), а одна фраза-цитата покрывает лишь часть, и судья ложно решает «добавлены
факты». Парсер судьи принимает и `да/нет`, и `yes/no`. При сбое сети — консервативно «не подтверждено».

Каждая строка прогона в панели раскрывает **сам ответ, список источников (с chunk_id) и цитаты** — чтобы
наглядно видеть, на чём основан вердикт.

## Как посмотреть (dev-панель «Индексация знаний (RAG)»)

1. `.\gradlew.bat run` → режим разработчика + ключ LLM. Композер → иконка-БД. **Шаг 1** — построить индекс.
2. **Шаг 2** — задать вопрос → под ответом С RAG видны **Источники** (файл › раздел · chunk_id) и **Цитаты**.
   Вопрос не из базы (кнопка-пример) → карточка помечается **🚫 режим «не знаю»**.
3. Блок **«День 24»** → «Проверить цитаты и источники (10 вопросов)»: сводка «источники N/10 · цитаты N/10 ·
   смысл N/10» + вопрос-ловушка → «не знаю».

## Границы

Цитата выбирается по лексическому совпадению с вопросом (не по тому, какую именно фразу «использовала» LLM) —
это осознанный компромисс ради детерминизма и гарантии дословности. Faithfulness-судья — отдельный LLM-вызов,
проверяется в GUI (LLM из headless-gradle не резолвится). Интеграция RAG в основной чат-оркестратор — отдельный шаг.

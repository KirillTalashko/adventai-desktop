# Контекстное окно и управление контекстом

## Принцип

Модель **не помнит ничего сама** — всё нужное передаётся в `messages` каждого запроса. Качество ответа =
качество переданного контекста. По умолчанию контекст собирается **под капотом** (режим «Авто»), но
пользователь может выбрать другой **режим памяти** — чип «Память» в композере (см. ниже).

## Режимы памяти (`domain/Memory.kt → MemoryMode`)

Селектор в композере (раскладка — `DESIGN_BRIEF.md`). Режим влияет ТОЛЬКО на объём истории и блоки
памяти диалога: жёсткие правила (инварианты), профиль пользователя и `[STATE]` задачи уходят в system
при ЛЮБОМ режиме.

| Режим (в коде) | Что уходит в запрос | Доп. вызов модели |
|---|---|---|
| `Auto` — «Авто» (по умолчанию) | конвейер ниже: вся история, пока окно свободно; при заполнении — последние N + два уровня свёртки | только при заполнении ≥30% |
| `Window` — «Только последние сообщения» | жёстко последние `WINDOW_N = 6` реплик, без блоков памяти | нет |
| `Facts` — «Ключевые факты» | последние N + блок `[СТРАТЕГИЧЕСКАЯ ПАМЯТЬ]` (устойчивые факты хвоста) | да, с гистерезисом |
| `Summary` — «Краткий пересказ» | последние N + блок `[ТАКТИЧЕСКОЕ РЕЗЮМЕ]` | да, с гистерезисом |
| `Full` — «Вся история» | весь диалог; при переполнении бюджета старые реплики режет предохранитель | нет |

- Выбор хранится в `~/.adventai/config.json` (`memoryMode`, строкой); неизвестное значение → `Auto`.
- Свёртку делает `MemoryPlanner` на **служебном** шлюзе (дешёвая модель; при локальной модели — та же
  локаль, без облака). Гистерезис `REFOLD_STEP = 6`: пересворачиваем, только когда хвост подрос на 6
  реплик — иначе платный вызов случался бы почти каждый ход.
- Стадийные лимиты оркестратора (EXECUTION 6, ASSIST 8) — поведенческий предохранитель, и режим
  «Вся история» их **не снимает**.
- Проверка без GUI: `.\gradlew.bat runMemoryModeCheck`.

## Единый конвейер режима «Авто» (`domain/Memory.kt → ContextAssembler`)

Каждый запрос собирается одинаково:

```
system( базовый промпт + [ДОЛГОВРЕМЕННАЯ] + [РАБОЧАЯ] [+ [СТРАТЕГИЧЕСКАЯ ПАМЯТЬ] + [ТАКТИЧЕСКОЕ РЕЗЮМЕ]] ) + последние N=12 реплик
```

- **Пока окно свободно** (заполнение < 30%): отправляется **вся история** — ничего не теряем.
- **При заполнении ≥ 30%**: старый хвост (всё старше последних N=12) сворачивается в **rolling summary**
  и подмешивается двумя уровнями — блоками `[СТРАТЕГИЧЕСКАЯ ПАМЯТЬ ДИАЛОГА]` (устойчивые факты/цели) и
  `[ТАКТИЧЕСКОЕ РЕЗЮМЕ]` (сводка недавнего хода); в `messages` идут только последние 12.

Смысл не теряется, потому что важное живёт в долговременной/рабочей памяти и в резюме (см. `MEMORY_MODEL.md`).

## Заполнение окна

- `contextFill` = `usage.prompt` последнего ответа ÷ `ModelOption.contextLimit` (`ui/ChatState.kt`).
- Лимиты в `data/Models.kt`: DeepSeek 65 536 · Llama/DeepSeek-V3 131 072 · Gemini 1 000 000.
- Порог авто-суммаризации — константа `ContextAssembler.SUMMARY_FILL = 0.30`.

## Где какая техника

| Техника | Слой | Под капотом |
|---|---|---|
| **Sliding window** | краткосрочная | последние N=12 реплик дословно |
| **Sticky facts** | рабочая (+ промоушен в долговременную) | факты задачи «прибиты», не выпадают при обрезке (сейчас — рабочая память вручную; авто-извлечение — TODO) |
| **Summary** | переполнение | свёртка старого хвоста при ≥30% |
| **Branching** | не про окно | отдельная фича: форк диалога для альтернатив, у каждой ветки своё чистое окно (TODO) |

## Токены

- `usage` (prompt/completion/total) сохраняется в каждом ответе (`Message.usage`).
- UI: чип под ответом + сумма по сессии в композере (+ стоимость через `ModelOption.costUsd`).
- Суммаризация работает **тихо** (без баннера). Бесплатные модели OpenRouter лимитятся (429) — клиент показывает причину.
